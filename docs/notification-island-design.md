# Windows 灵动岛的通知与窗口入口

## 应用发现与窗口切换

启用灵动岛和通知后，原生工作线程每两秒核对当前 Windows 会话的进程及顶层窗口。微信、Weixin 和 QQ 的可执行文件需要匹配受支持的文件名、产品信息及腾讯发布者签名。独立客户端暂时没有可激活窗口时保留后台状态，同一客户端的无窗口渲染子进程不占入口。

岛上用本次运行的实例编号区分多个窗口。点击入口时重新检查窗口有效性及进程归属和创建时间，先恢复最小化窗口，再请求置前。Windows 拒绝前置时返回错误。客户端退出后撤下入口、提醒及该文件的图标缓存。[Windows 前台窗口限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

## 应用图标和系统提醒

收起态显示状态环、本地时间及正在运行的应用图标。图标取自客户端 EXE 的原始资源，经 WIC 解码后缓存。展开态复用这些图标，每个可切换窗口有独立入口，超出可用空间时可以翻页。悬停、点击和读屏使用同一份原生布局。

红点表示 Windows 通知中心存在属于该应用、且发生于当前客户端运行期间的提醒。系统仅提供应用标识时，标记归属整个应用。收到通知不会展开岛体或切换前台。通知监听只处理应用标识、通知 ID 和创建时间，正文、账号、联系人和聊天记录均不进入岛体或页面快照。[Windows UserNotification 字段](https://learn.microsoft.com/en-us/uwp/api/windows.ui.notifications.usernotification)

## 设置与后台

设置页的「启用通知」统一控制进程发现、系统通知监听和岛上提醒。修改和恢复默认值都先进入草稿，点击保存后才提交。关闭通知会停止工作线程并清除实例及提醒。主窗口关闭到托盘后，原生岛仍按已保存的配置工作；关闭灵动岛会释放原生窗口和通知工作线程。

## 安装与系统权限

| 运行方式 | 窗口入口 | 系统通知 |
| --- | --- | --- |
| 浏览器打开设置页 | 可预览外观 | 不访问系统通知 |
| 普通开发进程、MSI 或 NSIS 安装 | Windows 原生发现和切换 | 缺少包身份时显示当前安装方式不支持 |
| 带仓库清单的 x64 MSIX | Windows 原生发现和切换 | 已获授权即可读取；系统报告尚未授权时可在设置页主动请求 |

可选 MSIX 清单声明 `userNotificationListener`。Windows 授权针对用户的系统通知，应用在本地仅处理已识别的运行客户端。首次授权从设置窗口的 UI 线程发起；拒绝后可打开 Windows 通知隐私设置。已有 MSI/NSIS 用户可继续沿用原安装方式。[微软通知监听说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/notification-listener)

**生成可签名的包。** 在已安装 Windows SDK 且能找到 `MakeAppx.exe` 的 x64 开发者 PowerShell 中，从仓库根目录运行以下命令。发布者参数填写实际签名证书的 Subject。若 Cargo 使用自定义输出目录，向脚本传入 `-Executable` 指定 x64 Release 可执行文件。

```powershell
pnpm tauri build --no-bundle
./scripts/package-notification-msix.ps1 -Publisher "CN=实际发布者"
```

默认输出 `src-tauri/target/zx-once.msix`。交付前使用与发布者匹配的受信任证书签名，再安装并从开始菜单的包入口启动。目标机器需要 WebView2。MSIX 的数据目录和启动项受包身份约束，跨安装方式切换时应保留现有配置备份。[Windows 桌面应用打包](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-manual-conversion)

## v2 桌面交互历史记录

以下记录对应更改前的界面与安装包。v3 的自动进程发现、托盘恢复及新版动效仍待实机验收。

2026-11-12 在 Windows 交互桌面启动独立配置的 Tauri 开发实例，保留默认悬停展开。使用两个模拟微信窗口、一个模拟 QQ 窗口，经过实际 Win32 窗口发现、岛体鼠标点击和系统前台切换。前台观测只记录这三个测试窗口。

| 操作 | 实际结果 |
| --- | --- |
| 从收起态点击微信，随后在岛外点击 | 156 × 44 DIP 胶囊展开为 328 × 168 DIP 面板，两条窗口入口可见；点岛外后恢复胶囊 |
| 在微信列表依次点第一行、第二行、第一行 | 系统前台依次为测试窗口 1、2、1，岛上选中标签也随之更新 |
| 从收起态直接点击只有一个窗口的 QQ | 首轮仅选中来源。修复后一次点击即前置唯一的 QQ 窗口；展开态仍可单独切换来源 |

修复将唯一窗口的操作 ID 绑定在收起态图标上。即使鼠标进入先触发展开，随后处理点击时仍能找到当时命中的目标。此情形已加入 Rust 回归测试。前端 12 项通过，Rust 默认套件 31 项通过，另有 2 项系统监听和 D3D11 专项在交互桌面单独通过。

## v2 签名 MSIX 与真实消息的历史记录

2026-11-12，在 Windows 11 26H2（26300.9974）为当前用户安装签名 MSIX，从包入口启动。Windows 签名校验通过，设置页显示「已获准读取系统通知」，正文预览保持关闭。此次安装直接取得已允许状态，未出现需要确认的首次授权弹窗。

| 真实消息 | 收起态胶囊的结果 |
| --- | --- |
| 微信 4.2.0.52 收到一条仅在微信内弹出的消息 | 用户确认 Windows 通知中心没有此条记录。微信、QQ 红点都保持关闭。微信系统提醒的亮起与清除尚未实测 |
| QQ 9.9.37 收到一条保留在 Windows 通知中心的提醒 | 旧包漏标；更新到同一包身份的修复版后，保留的同一条提醒点亮 QQ 红点，微信红点保持关闭 |
| 用户从 Windows 通知中心移除最后一条 QQ 提醒 | 收起态 QQ 红点从亮变灭，微信红点始终关闭 |

红点通过原生胶囊自身的辅助功能状态核对。验收结束后已卸载测试包，并核对机器级临时信任、个人签名证书和关联私钥均已移除。

## 后续实机验收

| 场景 | 应观察到的结果 |
| --- | --- |
| 两个微信窗口、一条微信通知，同时收到 QQ 提醒 | 两个应用各有红点；微信窗口分别可选；移除某应用最后一条通知仅清该应用标记 |
| MSI、签名 MSIX 的首次授权、拒绝、撤销及恢复 | 设置页能区分安装方式受限与用户拒绝，现有窗口入口继续可用 |
| 退出所有客户端，再启动同一应用 | 退出后入口和红点消失，旧提醒不会被当作新实例的提醒 |
| 快速移入移出、拖动、侧边停靠、混合 DPI、多屏热插拔 | 指针命中跟随可见区域，透明区可穿透，窗口切换不会落到旧实例 |
| 空闲与通知突发 | 空闲不持续呈现新帧；记录通知到可见红点的延迟、P95 帧耗时、CPU 与内存变化 |

窗口发现与激活、签名包获得通知访问、真实 QQ 提醒的归属与清除已有上述记录。微信系统提醒、授权拒绝与撤销，以及混合 DPI 和性能指标仍待对应环境验证。历史渲染数据见[性能基线](island-performance-baseline.md)与[迁移报告](island-performance-report.md)。
